Ինքնուրույն հոսթավորվող pool-ն աշխատում է **.113** մեքենայի վրա (`tomni-proxmox-113`)։ 2026-10-18-ից ի վեր
OmniRoute-ի յուրաքանչյուր runner ունի **մեկ դեր**, մեկ պիտակ և իր աշխատանքային բեռնվածքի
չափումներին համապատասխան հիշողության/CPU-ի բյուջե։ Turbopack-ի սլոթը ստանում է build-ի համար անհրաժեշտ ռեսուրսները, իսկ մյուս սլոթների չափերը համապատասխանում են դրանց
չափված առավելագույն բեռնվածություններին։ Մեքենան ռեսուրսները գերբաշխում է միայն այն դեպքում, երբ Turbopack-ի build-ը համընկնում է Release-Green-ի

(`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` /

## Տեղադրեք մաքրող սկրիպտը (մեկ անգամ՝ սերվերի վրա)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root)՝ յուրաքանչյուր 30 րոպեն մեկ, գրանցել /var/log/runner-janitor.log-ում
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof`-ը պարտադիր է․ նախքան ուղին հեռացնելը մաքրող սկրիպտը բաց
ֆայլերի մեկ ակնթարթային պատկերի միջոցով հաստատում է, որ այն չի օգտագործվում,
իսկ առանց այս գործիքի ոչինչ չի հեռացնում և հայտնում է այդ մասին
(exit 1)։ Ցանկացած փոփոխություն նախ փորձեք `--dry-run`-ով․ այն ճշգրիտ ցուցադրում է,
թե ինչ կաներ, և ոչինչ չի փոփոխում։

Յուրաքանչյուր գործարկման ժամանակ այն կատարում է հետևյալը․ մաքրում է մեր թողած մնացորդները (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`)՝ **tmpfs-ում 3 ժամ**, իսկ սկավառակի
`_work/_temp`-ում 24 ժամ մնալուց հետո, դադարեցնում է 75 րոպեից հին `next-build`-ը (ոչ մի առաջադրանք այդքան երկար չի աշխատում․
2026-08-27-ին մեկն աշխատել է 70 րոպե այն բանից հետո, երբ GitHub-ն իր առաջադրանքը կորած էր հայտարարել), հեռացնում է
այն ռաններների 48 ժամից հին checkout-ները, որոնց unit-ը **կանգնեցված է**, և նախազգուշացնում է, երբ սկավառակի օգտագործումը ≥ 85 % է, հիշողության PSI-ի
`full/avg60`-ը ≥ 10 % է, կամ listener-ների քանակը գերազանցում է `MAX_ACTIVE_RUNNERS`-ը (omniroute/այլ
բաշխմամբ)։ Exit 1 = ուշադրություն է պահանջվում․ կարդացեք լոգը։

75 րոպեի կանոնը չի հայտնաբերում այն build-ը, որի առաջադրանքից GitHub-ն արդեն հրաժարվել է։ Երբ
`Runner.Listener`-ը չի կարողանում թարմացնել իր առաջադրանքը, `_diag/Runner_*.log`-ում երևում է
`POST request to …/renewjob timed out after 100 seconds`, API-ն առաջադրանքի կարգավիճակը նշում է որպես `completed`
(ձախողված)՝ վերջին հաջող թարմացումից մոտ տասը րոպե անց, իսկ `next-build`-ը շարունակում է աշխատել՝
առանց կցված առաջադրանքի (2026-10-18-ին #17066-ի Build-ը ձախողված էր նշվել 19:43-ին, իսկ դրա build-ը հինգ րոպե անց դեռ
զբաղեցնում էր 40 GB)։ Հաստատեք ref-ը ամենանոր `_diag/Worker_*.log`-ում, ապա
PID-ով SIGTERM ուղարկեք միայն build-ի պրոցեսների ծառին՝ `next-build`, `npm run build`, `build-next-isolated.mjs` և
`_work`-ի worker-ներին։ Երբեք մի դիպչեք `Runner.Listener`-ին, `RunnerService.js`-ին կամ `Runner.Worker`-ին․
worker-ը առաջադրանքը նշում է որպես չեղարկված, իսկ listener-ն ինքնուրույն կրկին անցնում է առցանց վիճակի։

## Runner միավորներ․ KillMode

Runner-ի լռելյայն `KillMode=process` կարգավորումը միավորի կանգնեցման կամ վերագործարկման ժամանակ կենդանի է թողնում `Runner.Worker → npm → next-build` շղթան․ առանց որևէ առաջադրանքի մնացած որբ build-ը շարունակում է սպառել RAM և CPU։ OmniRoute-ի յուրաքանչյուր միավոր ունի լրացուցիչ կարգավորման ֆայլ՝ (`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`) `KillMode=mixed` արժեքով․ նախ SIGTERM է ուղարկվում listener-ին, ապա `TimeoutStop`-ի պահին SIGKILL՝ ամբողջ cgroup-ին։ Այն ուժի մեջ է մտնում միավորի հաջորդ վերագործարկման ժամանակ․ վերագործարկեք **միաժամանակ միայն մեկ runner և միայն այն ժամանակ, երբ այն անգործուն է**՝ անգործունության ստուգումն ու վերագործարկումը կատարելով նույն հրամանով։
