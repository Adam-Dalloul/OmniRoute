સેલ્ફ-હોસ્ટેડ પૂલ **.113** મશીન (`tomni-proxmox-113`) પર ચાલે છે. 2026-10-18થી દરેક
OmniRoute runner પાસે **એક ભૂમિકા**, એક લેબલ અને તેના વર્કલોડના માપેલા વપરાશ અનુસાર નક્કી કરાયેલ મેમરી/CPU બજેટ છે.
Turbopack સ્લોટને બિલ્ડ માટે જરૂરી સંસાધનો મળે છે; અન્ય સ્લોટ્સ તેમના
માપેલા મહત્તમ વપરાશ અનુસાર ગોઠવાયેલા છે. જ્યારે Turbopack બિલ્ડ, Release-Green
webpack બિલ્ડ અને lint જોબ એકસાથે ચાલે ત્યારે જ મશીન ઓવરકમિટ કરે છે; હોસ્ટ swap (16 GB) તેને સંભાળી લે છે, અને pull-request Builds

## જૅનિટર ઇન્સ્ટોલ કરો (એક વખત, મશીન પર)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): દર 30 મિનિટે, /var/log/runner-janitor.log માં લૉગ કરો
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` આવશ્યક છે: જૅનિટર કોઈ પાથને દૂર કરતાં પહેલાં ખુલ્લી ફાઇલોનો એક સ્નૅપશૉટ લઈને ખાતરી કરે છે કે તે નિષ્ક્રિય છે; આ ટૂલ ન હોય તો તે કંઈ દૂર કરતું નથી અને તેવું જણાવે છે
(exit 1). કોઈપણ ફેરફાર પહેલાં `--dry-run` વડે અજમાવો — તે બરાબર શું કરશે તે પ્રિન્ટ કરે છે
અને કશાને સ્પર્શતું નથી.

દરેક રન વખતે તે શું કરે છે: **tmpfs પર 3 કલાક** અને ડિસ્ક પરના
`_work/_temp` માં 24 કલાક પછી આપણા પોતાના અવશેષો (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) સાફ કરે છે; 75 મિનિટથી જૂનું `next-build` બંધ કરે છે (કોઈ જૉબ આટલો લાંબો ચાલતો નથી —
2026-08-27 ના રોજ GitHub એ તેનો જૉબ ગુમ થયેલો જાહેર કર્યા પછી એક જૉબ 70 મિનિટ ચાલ્યો હતો); જે રનર્સનું યુનિટ **બંધ** છે તેમના 48 કલાક જૂના
ચેકઆઉટ્સ દૂર કરે છે; ડિસ્ક ≥ 85 %, મેમરી PSI
`full/avg60` ≥ 10 %, અને `MAX_ACTIVE_RUNNERS` કરતાં વધુ લિસનર્સ હોય ત્યારે ચેતવણી આપે છે (omniroute/અન્ય વિભાજન સાથે). Exit 1 = ધ્યાન આપવું જરૂરી છે; લૉગ વાંચો.

75 મિનિટનો નિયમ એવા બિલ્ડને પકડતો નથી જેના જૉબને GitHub પહેલેથી જ છોડી ચૂક્યું હોય. જ્યારે
`Runner.Listener` તેના જૉબને રિન્યૂ કરી શકતું નથી, ત્યારે `_diag/Runner_*.log` માં
`POST request to …/renewjob timed out after 100 seconds` દેખાય છે, API છેલ્લી સફળ રિન્યૂઅલના લગભગ દસ મિનિટ પછી જૉબને `completed`
(નિષ્ફળ) તરીકે દર્શાવે છે, અને કોઈ જૉબ જોડાયેલો ન હોવા છતાં `next-build` ચાલતું રહે છે
(2026-10-18: #17066 નું Build 19:43 વાગ્યે નિષ્ફળ થયું હતું અને પાંચ મિનિટ પછી પણ તેનું બિલ્ડ
40 GB રોકી રહ્યું હતું). સૌથી નવા `_diag/Worker_*.log` માં ref ની ખાતરી કરો, પછી
ફક્ત બિલ્ડ ટ્રીને PID દ્વારા SIGTERM મોકલો — `next-build`, `npm run build`, `build-next-isolated.mjs` અને
`_work` વર્કર્સને. `Runner.Listener`, `RunnerService.js` અથવા `Runner.Worker` ને ક્યારેય સ્પર્શશો નહીં:
વર્કર જૉબને રદ થયેલો જણાવે છે અને લિસનર પોતાની મેળે ફરી ઑનલાઇન થઈ જાય છે.

## રનર યુનિટ્સ: KillMode

રનરનું ડિફૉલ્ટ `KillMode=process`, યુનિટને બંધ અથવા રીસ્ટાર્ટ કરવામાં આવે ત્યારે `Runner.Worker → npm → next-build`ને ચાલુ રાખે છે — કોઈ જોબ જોડાયેલી ન હોવા છતાં અનાથ બિલ્ડ RAM અને CPU વાપરતું રહે છે. દરેક OmniRoute યુનિટમાં
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ડ્રૉપ-ઇન છે, જેમાં `KillMode=mixed` છે: પહેલાં listenerને SIGTERM અને
`TimeoutStop` પર આખા cgroupને SIGKILL. તે યુનિટના આગામી રીસ્ટાર્ટ વખતે અમલમાં આવે છે — **એક સમયે માત્ર એક રનરને, અને તે નિષ્ક્રિય હોય ત્યારે જ રીસ્ટાર્ટ કરો**, તેમજ નિષ્ક્રિયતાની ચકાસણી અને રીસ્ટાર્ટ એક જ કમાન્ડમાં કરો.
